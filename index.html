What it does

Five capabilities, one rule: every number has a source.

1inch already runs Dune queries and dashboards. This concept adds a validated-metrics layer and a grounded AI workflow on top — complementing that foundation, not replacing it.

Provenance-first multi-chain dashboard

KPIs, trends, chain distribution, address-keyed token pairs and anomaly alerts — all filters update every chart and the narrative consistently. Each panel shows which query, execution and freshness produced it.

Real Dune API integration

SQL & saved-query execution, status polling, paginated results, cancel, retries, rate limits, credit budgets and cache — keys stay server-side; page renders never spend credits.

Grounded AI analyst

Findings, interpretation and evidence for every answer. The model picks a validated analysis and phrases facts; a validator rejects any unproven number.

Data reliability, reported honestly

Application health, upstream freshness and validation checks — null prices, duplicate keys, completeness, aggregate-vs-record consistency, SQL-vs-app anomaly agreement — are separated. When Dune refuses an execution, the real error is shown.

Covered-set aggregator comparison

1inch vs 0x, CoW, Odos and KyberSwap from the same curated table and window — explicitly a covered-set comparison, with a peer check asking “is this change unique to 1inch?”

Data methodology

Most analytics errors are grain errors, not math errors.

Validating the starting query surfaced the traps below. The platform reports each count separately and never adds non-additive metrics.

01

Records ≠ transactions ≠ addresses

A transaction can hold several aggregator records; distinct addresses are not additive across days or chains — so window counts use GROUPING SETS.

02

A routed swap appears twice

Once in dex_aggregator.trades, again as execution steps in dex.trades. The two tables are never summed.

03

tx_from is often a resolver

In intent-based flows (Fusion, CoW) the sender submits for the user — the platform reports trader (taker) and initiator (tx_from) addresses side by side.

04

Second-side limit-order rows

Direct limit-order fills are emitted from both users’ perspectives (evt_index = -1); their share of volume is surfaced instead of silently double counted.

Grounded AI

The model explains. It never computes, and it never writes SQL.

Every answer runs the same pipeline. The two LLM steps are bounded by schemas; everything numeric happens in deterministic code, and a validator checks the prose before it is shown. Without an LLM key, a clearly labelled rule-based mode answers instead.

“Why did aggregator volume change on Arbitrum over the last seven days?”

Observed volume fell from $27.09M to $15.12M (-44.2%).

Count effect -$4.62M, average-size effect -$7.35M — consistent with fewer large trades.

Covered peers moved -10.7%; the covered-set share went 55.0% → 43.3%, so part of the change looks 1inch-specific.

✕ rejected by validator

“Volume dropped 52% because of a competitor incentive.”

52% matches no computed fact, and the causal claim has no evidence → the sentence is removed and listed in the validation report.

Synthetic demo values. Count + size effects sum exactly to the change (Shapley split). Peer comparison separates market-wide from 1inch-specific movement.
